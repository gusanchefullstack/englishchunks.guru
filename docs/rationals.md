# Rationale: options, decisions and evidence

A record of the choices made while building EnglishChunks.guru, from the first draft (2026-10-16) to the move onto free tiers (2026-11-21): what the options were, what was chosen, why, and what proved it. ## 1. Starting point

The project began as a written product brief ([`my-drafts/specs.md`](../my-drafts/specs.md)) with screen designs in Figma. Several of the defining technical calls were already in that brief, before any code:

- **Teach chunks, not words**, at the learner's CEFR level, with a fixed daily flow: Learn → Speak (two tries) → Write → Read aloud → Daily score.
- **Open models at the core**: an open-weight LLM (Gemma 4 26B A4B) for tips and grading, and a self-hosted speech pipeline (Silero VAD → Parakeet → wav2vec2 phonemes) for pronunciation, instead of a closed speech API.
- **Deterministic pedagogy**: "keep the IPA-to-friendly-hint mapping in app (a small table of the ~40 English sounds), not generated by Gemma … Gemma only adds the warm, personal tone around it."
- **An independent, cheaper model** to audit the preloaded chunk library.
- **Cost rules**: generate audio only when the learner presses play; use ElevenLabs Flash (half the credits); quantize the speech models to int8 to fit a smaller server; stay on Vercel Hobby while testing; take real payments only after an explicit switch by the admin; **"test the scoring quality first."**

The build followed spec-driven development with [Spec Kit](https://github.com/github/spec-kit): constitution → spec → clarify → plan → tasks → analyze → implement.

## 2. Principles that drove the decisions

The [constitution](../.specify/memory/constitution.md) (ratified as v1.1.0 on 2026-10-16, v1.2.1 today) turned the brief into rules that later decisions were checked against:

| Principle | What it forces |
|---|---|
| I. Open-source AI at the core (non-negotiable) | Speech scoring on self-hosted open models on infrastructure the project controls; open-weight LLMs; no closed speech API. |
| II. Deterministic pedagogy, generated warmth | Sound hints come from a curated table; the LLM only phrases around them; the chunk library is audited by an independent model. |
| III. Test-first quality gates (non-negotiable) | Every change goes through CI: lint, types, unit/integration, Playwright e2e with axe, scoring tests, secret scan. |
| IV. Security, privacy and payment safety | Recordings are processed in memory and never stored or logged; no card data touches the app; verified webhooks; no secrets in the repo. |
| V. Cost-conscious by default | Lazy, cached TTS; cheapest adequate model tier; since v1.2.0, free tiers and scale-to-zero over fixed servers, and **code before paid capacity**. |
| VI. Learner-first, inclusive design | Accessible (WCAG AA), works with keyboard only, friendly to all ages; feedback in simple English at the learner's level. |
| VII. Type safety and simplicity | TypeScript end to end, one web deployable; a second (Python) deployable only because the speech models need it. |

Every change went through the Spec Kit amendment flow rather than quietly breaking a rule: **v1.1.1** (2026-10-16) applied the cross-artifact analysis fixes, **v1.2.0** (2026-11-15) to allow Google Cloud Run as project-controlled scoring infrastructure and to make "free tier and scale-to-zero first" explicit, and **v1.2.1** (2026-11-21) to name Cloudflare R2 as object storage.

## 4. Decisions by area

Each row lists the options weighed, the choice, and the evidence behind it.

### Product and pedagogy

| Question | Options | Decision | Why / evidence |
|---|---|---|---|
| What to teach | Single words; chunks | Chunks (lexical and grammatical), by CEFR level | Brief: fluent speakers think in pre-assembled blocks. |
| Where sound hints come from | LLM-generated; curated table | Curated table of ~40 IPA hints (`sound_hint`), shared by web and scoring | Always correct and consistent; the LLM coach (Mina) only adds warmth, with a fallback tip if it's slow. |
| Feedback language | Learner's mother tongue; English | Simple English matched to the learner's CEFR level | Clarification 2026-10-16. |
| Library quality | Manual curation; self-audit; independent audit | Gemma drafts, IPA from the scoring service, **gpt-oss-20b audits**, failures go to an admin queue | Self-audit shares the same blind spots (plan, Complexity Tracking). |
| Duplicate suggestions | Embedding similarity; normalisation + trigram | Deterministic normalisation + `pg_trgm` | Explainable, cheap, no extra model (R13). |
| Ranking | Everyone together; by level band | Level band by default, toggle to overall; opt-out; **first name only** (2026-11-15) | Fair comparison; shows less personal data. |
| Sign-ups while free | Open; invite-only | Open up to an admin-set cap (default 200), then a waitlist with invites | Clarification 2026-10-16: controls cost and load during testing. |
| Payments | Charge from day one; switch on later | Stripe Billing built and tested but **off** until an admin types `ACTIVATE`; app-managed 7-day trial | Brief: no real payments until explicitly started. |
| Account deletion and reminders | — | Self-service deletion that erases personal data immediately; one optional daily reminder at the learner's hour, with one-click unsubscribe | Clarifications 2026-10-16. |

### AI models

| Question | Options | Decision | Why / evidence |
|---|---|---|---|
| Tips and writing grades | Closed models; Gemma 4 31B; self-hosted Gemma; Gemma 4 26B A4B | **Gemma 4 26B A4B** via Vercel AI Gateway, model id in config | Open-weight, cheapest Gemma 4, MoE with ~4B active params; CPU self-hosting too slow (R1). |
| Slow LLM tail | Wait; pay for faster hosting; timeout + fallback | 5 s on Gemma, then one retry on open-weight **gpt-oss-20b** (12 s), then "try again" | Gemma providers had a 30+ s tail; writing feedback hit a 146 s p95 before the fix (R1). |
| Structured output | Trust provider JSON mode; state the schema | Schema also in the system prompt, still validated with Zod | Gemma's gateway provider ignored JSON-schema mode and the model invented keys; mocked tests could not catch it. |
| Perceived latency | Bigger server; stream | Score streamed first (NDJSON), tip a moment later | Removed the 2–3 s the learner actually felt, at no cost. |

### Speech scoring

| Question | Options | Decision | Why / evidence |
|---|---|---|---|
| Pronunciation engine | Closed speech APIs; Kaldi GOP; Montreal Forced Aligner; Whisper; open ONNX pipeline | Silero VAD → **Parakeet TDT 0.6B v2** (words, fluency) → **wav2vec2 espeak phonemes** (CTC + GOP) | Open, CPU-friendly; Whisper slower on CPU and hallucinates on short clips (R4–R6). |
| Runtime | PyTorch; ONNX int8 | ONNX Runtime, **int8**, no torch | ~4× less memory; fits a 4 GB box (brief cost note #4). |
| Score formula | Learned regressor; weighted blend | 0.5 phonemes + 0.3 words + 0.2 fluency, weights in config | Not enough labelled data for a regressor (R7). |
| Calibration data | In-app recordings; external sets | speechocean762 + consenting volunteers, **never learner recordings** | Keeps "recordings deleted immediately" absolute. |
| Proof of quality | — | SC-005 ≥ 85 % correct pair ranking | **89.1 %** over 66,189 pairs (laptop), **88.8 %** on Cloud Run. |
| Accuracy fixes | — | In-order recall (LCS) for words; average GOP in probability space; weakest sounds only below 85 | Found by real browser recordings, not by fakes (BENCHMARKS). |
| Latency without upsizing | 8 GB Droplet; code | ASR and phonemes in parallel (1 + 2 threads) | −10 % server time; p95 1.68 s on 2 vCPU, no resize. |

### Privacy and security

| Question | Options | Decision | Why / evidence |
|---|---|---|---|
| Recording transport | Direct browser → scorer with signed tokens; via the web app | Browser → Next.js route → HMAC-signed HTTPS → scorer, all in memory | One trusted path; scores can't be forged by the client (R8). |
| Never touching disk | — | Reject oversized bodies **before** parsing; decode from `BytesIO`; tmpfs only | Starlette spools uploads > 1 MB to disk; Docker tmpfs is `noexec` by default. |
| Logs | — | Metadata only (durations, ids), never transcripts or sentences | Checked again in Cloud Run request logs after the move. |
| Auth | Auth.js; Clerk / Auth0; Better Auth | **Better Auth** with Drizzle, email verification, Google sign-in | User data stays in our database (R11). Implicit Google account linking disabled to prevent account takeover (caught by `/speckit-analyze`). |
| Payments | Stripe Elements; Lemon Squeezy; Stripe Checkout | Hosted Checkout + Customer Portal, restricted keys, signature-verified idempotent webhooks | No card data in the app (R16). |
| Web hardening | — | CSP and security headers, per-IP rate limits, admin area returns 404 to non-admins, gitleaks in CI | T150. |
| Storage access | Public bucket; private bucket | **Private R2 bucket**; signed URLs only; per-learner audio never served through the public `/media` route | 2026-11-21. |

### Web, data and quality

| Question | Options | Decision | Why / evidence |
|---|---|---|---|
| Framework | Separate Node API; Next.js full stack | **Next.js 16** App Router, Server Actions, Route Handlers, Cache Components | One deployable (Principle VII). |
| Database | Prisma; Drizzle | **Neon Postgres + Drizzle** | Typed, SQL-first, light cold starts (R12). |
| Connection drops on serverless | Disable auto-suspend (paid); pool per request; HTTP driver; fix the pool | Attach the pool to the function lifecycle, idle timeout, error listener, retry reads only | 16 failed sign-in lookups in 2 days; writes never retried to avoid double-applying (R21). |
| Testing | — | Vitest + MSW, Playwright with axe, pytest, all offline without real keys | Real-path smoke tests still found bugs every fake had hidden. |
| Accessibility | — | Keyboard-only session, `aria-busy` instead of `disabled`, AA-safe palette | T147. |

## 5. How the hosting got to $0

The goal set on 2026-11-15: keep englishchunks.guru **free forever for everybody**, without lowering the quality of speech conversion and analysis. Fixed hosting was about $33/month.

### Speech scoring: $28 → $0

| Option | Verdict |
|---|---|
| Keep the DigitalOcean Droplet (`s-2vcpu-4gb-amd`) | Works, but $28/month for a server idle most of the day. |
| Oracle Cloud Always Free (ARM) | Rejected: the free ARM allowance was halved to 2 OCPU / 12 GB, idle machines get reclaimed, and ARM changes int8 numerics. |
| Vercel Hobby functions | Rejected: 4 CPU-hours/month shared with the site, and overage pauses the whole site. |
| Render free | Rejected: 0.1 CPU / 512 MB can't hold ~950 MB of models. |
| Hugging Face Spaces, Modal | Rejected: demo platform with unclear free CPU availability; promotional credits. |
| **Google Cloud Run** | **Chosen**: scale-to-zero, request-based billing inside the free grant (≈3 vCPU-seconds per score), a container the project builds and controls. |

How it was proven before switching:

- A separate test service with the same image and **sha256-identical models**.
- **gen1 vs gen2** compared: model load ~31 s vs ~10.5 s, so gen2.
- Calibration rerun over HTTP: **88.8 %** vs the 89.1 % baseline (target 85 %).
- Cold start measured (17.8 s), then hidden with a signed `GET /v1/warm` sent when a learner opens practice, plus a 30 s client timeout as a backstop.
- Production smoke test: p50 1.66 s, p95 2.33 s, 0 failures. A real practice session on the live site before calling it done.
- `max-instances 1` as the spend cap (budgets only alert), and a $1 budget alert.
- The Droplet stayed as a fallback for a week, with rollback steps documented, and was deleted only after a clean production week (48 successful calls, 0 errors).

### Hourly job: on time, $0

| Option | Verdict |
|---|---|
| Vercel Pro cron | Rejected: $20/month during free testing. |
| systemd timer on the Droplet | Worked, but the Droplet was going away. |
| GitHub Actions schedule | Tried first (free), but measured **17 runs in 5 days** (every 6–9 hours), so reminders arrived late. Kept as a manual trigger. |
| **Google Cloud Scheduler** | **Chosen**: on time every hour, free tier covers 3 jobs; the shared cron secret was rotated in the same step. |

### Files: $5 → $0

| Option | Verdict |
|---|---|
| Keep DigitalOcean Spaces | $5/month minimum for 24 MB of files. |
| Google Cloud Storage | ~5 GB free but only ~50K reads a month; every audio play counts. |
| **Cloudflare R2** | **Chosen**: 10 GB, 1M writes and 10M reads free, no egress fees, same S3 API. |

R2 has no per-file public/private setting, so the bucket stays **private** and every read is a signed URL: audio URLs are signed per hour window so browsers still cache them, and avatars and the landing video get stable `/media/<key>` addresses that redirect to a signed URL. All 244 files were copied and verified before the switch, and a full practice on production confirmed audio before Spaces was retired.

## 6. Patterns of judgement

- **Quality first, then cost.** "Test the scoring quality first" set the order of the whole build: the scoring spike and calibration ran before any UI, and every later hosting move had to match the calibration score before it shipped.
- **Code before capacity.** Latency was fixed with parallelism and streaming, never by upsizing; the 8 GB resize planned in the research was never needed.
- **Measure, don't assume.** GitHub's "hourly" schedule, Gemma's latency tail, Neon's dropped sockets and gen1 vs gen2 start times were all measured before deciding.
- **Reversible steps first.** New hosts ran beside the old ones; the old host stayed as a fallback until production was clean; destructive steps (deleting the Droplet, the bucket) came last and with explicit confirmation.
- **Privacy by construction, not by policy.** Recordings never reach disk, logs or a third party; calibration uses external consented data; the ranking shows first names only; storage is private by default.
- **Rules change through the front door.** When a principle needed to change (Cloud Run, R2), the constitution was amended with a version bump instead of being bent.
- **Free for learners, safe for the owner.** Billing is built and tested but switched off; sign-ups are capped with a waitlist; spending caps sit on every host that could scale.

## 7. Open decisions

- **Billing go-live**: Stripe test-mode demo, Vercel Pro (Hobby is non-commercial), restricted live keys, Stripe Tax decision.
- **Library size**: grow the audited library to ~1,000 chunks (177 practicable at launch).
- **Real-device benchmark**: add iOS Safari and Android Chrome recordings to the scoring benchmark.
- **Text-to-speech**: an open-source voice (Kokoro or Piper) remains a possible swap behind the TTS adapter if credits become a cost (R9).
- **Premium "Guru conversation"** and an interface in the learner's mother tongue.
